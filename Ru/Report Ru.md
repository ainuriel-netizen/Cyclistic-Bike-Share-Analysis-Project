## ТЕХНИЧЕСКИЕ ВЫЗОВЫ И РЕШЕНИЯ

### MySQL Timeout Issues (Error 2013)

**Проблема:**
При работе с таблицей из 11.4M строк часто возникала ошибка `Error 2013: Lost connection to MySQL server during query`. Это происходило при:
- Больших UPDATE запросах ко всей таблице сразу
- Сложных SELECT запросах с агрегацией
- Попытке использования GUI инструмента (MySQL Workbench)

**Причины:**
- Стандартные таймауты MySQL (30 сек) недостаточны для обработки 11M строк
- Сетевые таймауты при больших результатах
- GUI интерфейсы (Workbench) имеют собственные ограничения

**Опробованные решения:**

1. ✅ **Батч-обработка по месяцам (Python)** — наиболее надежное решение
   - Вместо UPDATE для всех 11.4M строк одновременно
   - UPDATE для каждого месяца отдельно (100k–600k строк за раз)
   - Результат: надежно, без таймаутов

2. ⚠️ **Увеличение таймаутов MySQL** — частично помогает
   - `SET SESSION max_execution_time = 3600000`
   - Помогает, но не полностью решает проблему

3. ✅ **Создание индексов** — улучшает SELECT запросы
   - Индексы на часто используемых столбцах
   - SELECT запросы работают значительно быстрее
   - **Недостаток:** индексы занимают дополнительное место (~1 GB на таблицу 3.2 GB)

### Текущая конфигурация MySQL:

| Параметр | Значение |
|----------|----------|
| **Размер данных** | 3,178.92 MB (~3.2 GB) |
| **Размер индексов** | 1,069.00 MB (~1 GB) |
| **Общий размер** | 4,247.92 MB (~4.2 GB) |
| **Количество строк** | 11,122,047 |
| **Индексы** | ride_length_minutes, member_casual |

**Вывод:** MySQL имеет встроенные ограничения для больших аналитических операций на наборах 10M+ строк. Решение — использовать специализированные OLAP базы данных, такие как ClickHouse.

## ПЕРЕХОД К CLICKHOUSE

### Архитектура решения:

**MySQL** (OLTP):
- ✅ Надёжное хранилище исходных данных
- ✅ 11.1M чистых записей + 278k отменённых + 13k долгих поездок
- ✅ Резервная копия для верификации данных

- ✅ Специализирована на аналитических запросах (GROUP BY, агрегации)
- ✅ Работает с 11M+ строк без таймаутов
- ✅ Колонарное хранилище — очень эффективное сжатие
- ✅ Партиции по месяцам — быстрый поиск

## АНАЛИЗ И ВЫВОДЫ (Analyze)

### Ключевые аналитические инсайты

После загрузки всех 11.1M поездок в ClickHouse и создания интерактивных Power BI дашбордов выявлены следующие критические паттерны:

**1. Объемы и сезонность**

Подписчики генерируют **64% всех поездок** и сохраняют стабильное использование в течение года. Разовые пользователи демонстрируют **ярко выраженный летний пик** (май-сентябрь) с почти нулевым использованием зимой.

**Вывод:** Подписчики = стабильный доход; Разовые пользователи = сезонная волатильность

**2. Длительность поездок**

- Разовые пользователи: 19-22 минуты в среднем
- Подписчики: 11-12 минут в среднем

**Разовые пользователи ездят в 1.5-2 раза дольше.** Это указывает на разные сценарии: Подписчики = коммутинг (быстро), Разовые пользователи = досуг (долгие поездки).

**3. Дни недели и время суток**

- **Будни:** Подписчики лидируют 2:1 (коммутинг на работу)
- **Выходные:** Разовые пользователи активнее (отдых, парки)
- **Пиковые часы:** День (12:00-18:00) для обеих групп
- **Утро:** Разовые пользователи показывают низкую активность, Подписчики активны с 07:00

**4. Паттерны маршрутов и география**

- ** Подписчики (A→B):** Четкие маршруты дом-работа, транспортные узлы (Ellis Ave, University Ave). **Утилитарный транспорт.**
- ** Разовые пользователи (A→A):** Круговые прогулочные маршруты (парки, озёра: DuSable Lake, Streeter Dr, Millennium Park). **Досуговый сценарий.**

## ДЕЙСТВИЯ И РЕКОМЕНДАЦИИ (Act)

На основе данные-driven анализа рекомендуются три ключевых действия для конверсии Разовые пользователи → Подписчики:

### TOP-3 Рекомендации

**1. Гибкие подписочные тарифы**

**Действие:** Ввести "Подписку выходных дней" и "Летнюю подписку". Это снимет барьер покупки годовой подписки у тех, кто не планирует кататься зимой или ездит только по выходным.

**Почему работает:**
- Разовые пользователи показывают летний пик и практически не используют сервис зимой
- Выходные гораздо активнее будней для разовых пользователей
- Гибкие тарифы убирают финансовый барьер для сезонных пользователей

**Ожидаемый результат:** Конверсия разового трафика в подписчиков


**2. Сезонный таргетинг и триггеры выгоды**

**Действие:** Запустить весной кампанию "**3 месяца лета занимают весь год**" для разовых пользователей и отправлять push-уведомления с расчетом индивидуальной экономии при активных поездках.

**Почему работает:**
- Разовые пользователи активны все лето (май-сентябрь) — достаточно для окупа годовой подписки
- Расчет персональной экономии сильнее, чем генерические предложения
- Push в момент пика активности ловит пользователя с нужным эмоциональным состоянием

**Ожидаемый результат:** Точный ретаргетинг с высокой конверсией


**3. Динамическое ценообразование для разовых поездок**

**Действие:** Ввести надбавки за пиковые часы и минуты для разовых поездок, повысив привлекательность фиксированной годовой подписки.

**Почему работает:**
- Разовые пользователи ездят дольше (19-22 мин) → больше минут = выше цена
- Пиковые часы (afternoon) имеют спрос → можно поднять цену
- Когда разовая поездка стоит $7-8, годовая подписка за $39/месяц выглядит выгоднее

**Ожидаемый результат:** Рост ценности подписки в глазах разовых пользователей
